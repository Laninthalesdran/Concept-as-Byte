# Talkit — ZophiaE chat appliance

One window, no install, no internet, no Python. Type English; LidiaE
(the translator) turns it into annotated Simple English, the codec
turns that into concept bytes, a ZophiaE model answers in bytes, and
the same chain runs backward to English. The Reasoning pane shows the
model working: for every generated byte, the candidate probabilities
it weighed and the attention it paid across the context, per layer and
head.

Everything on screen is honest: the annotated stream IS what the model
said; unrenderable or undecodable output is shown raw and labeled,
never papered over.

## What the shipped model can do

The bundled model is **ZophiaE 25M v3** — 25,377,152 parameters,
trained on a single consumer GPU in under two hours total, at exactly
10 encoded bytes per parameter per phase ("neochinchilla"). It is a
**calibrated logical-verdict engine**, not a general chatbot. Measured
on 2,024 fresh questions proven (by hash, against every training
document) never to have been seen:

| | |
|---|---|
| four-way verdict accuracy (YES / NO / UNKNOWN / OPEN) | **89.1%** (floor for any constant answerer: 25%) |
| refusal precision — when it says "we can not say", it's right | **98.1%** |
| END discipline — answers close their own frame | ~99% |
| the same architecture at half the data ration | 35.9% |

It computes (real division, real counting — change a number and the
verdict follows the arithmetic, not the template), it refuses when the
premises genuinely underdetermine the answer, and it explains which
rule it used. The **Verify tab reproduces these numbers on your own
machine** — you are not asked to believe a screenshot.

Honest scope: this is rule-generalization inside eleven trained logic
families (propositional rules, syllogisms, temporal/interval
reasoning, quantities, evidence-vetting, game tactics, invariants,
proof patterns, and more). It is not open-domain chat; vocabulary is
bounded by the dictionary; constraint-satisfaction puzzles (family f6)
sit near 50%. Questions outside the register are **dropped with a
stated reason**, never guessed at.

## Setup

Unzip (or copy) the folder anywhere. Double-click `talkit.exe`. That
is the whole install — the `assets/` folder must simply stay beside
the exe.

**Asking it things.** Short declarative facts, one per sentence, then
optionally an if-then rule, then exactly one question. Digits for
numbers. *does / is / can / will* asks get yes, no, or "we can not
say"; *what / which / why / how many* asks get an open answer with the
work shown. **[Questions.md](Questions.md) is the full playbook** —
every trained question family with paste-ready examples, the
change-a-number game, and an honest map of where the box ends.

> john has 56 breads. the group uses 4 breads each month. the bread
> must last 8 months. if the bread does not last, then the sun sets.
> does the sun set?

(That one is the refusal branch: 56/4 = 14 ≥ 8, the bread lasts, the
rule is silent — the model shows the division and declines. Change 8
to 15 and it answers yes.)

## Run

    talkit                      the window
    talkit gui "question"       the window, question asked on launch
    talkit serve [--port 8484] [--model <name>] [--max-new N]
                                local HTTP server (see API below)
    talkit probe [dir] [n]      the four-way verdict probe, headless
    talkit trace "question"     headless turn + harness dump (debug)
    talkit gen <hex>            raw byte-level generation
    talkit corpus <folder>      a folder of files -> corpus.bin
    talkit eagle <img> / bat <wav>   media -> concept bytes
    talkit parity-model | parity-codec | parity-lidiae   the gates

`TALKIT_MODEL=<name>` (folder name or display name) selects the model
for the headless commands.

## Bundle layout — and adding models

    talkit.exe
    assets/
      table/*.tsv                  the dictionary (shared by every model)
      models/<name>/
        model.safetensors          fp32 weights
        config.json                dims + display name + provenance
      model.safetensors            (optional) a default model at the top
      config.json                  level, listed first when present

Models are **discovered, not registered**: drop another
`assets/models/<name>/` folder in and it appears in the window's
picker on next launch. With a single model present the picker hides
and the header names it. Each `config.json` carries `d_model`,
`n_layers`, `n_heads`, `n_kv`, `d_ff`, `seq`, and `name` — one exe
serves every ZophiaE size.

## Using the window

- **Chat** — type and press **Enter** (or Send). The reply bubble is
  stamped with the answering model's name, and carries a **verdict
  chip**: YES / NO / UNKNOWN / OPEN plus the generation's mean and
  minimum step probability — how sure it was, byte by byte.
- **Reasoning pane** (right) — click any MODEL bubble: per-step
  candidate probabilities and per-layer/head attention over the
  context. The `bytes` toggle shows raw hex.
- **Model picker** (header) — switch models between turns; loading
  happens on a background thread. Turns already on screen keep their
  stamps, so answers from different models stay tellable-apart.
- **A/B** (header) — pick a second model and every question is
  answered by both, one bubble each. The stamps are the scorecard.
- **Sampling** (header, right) — `temp 0.00` is the default: greedy,
  deterministic, same answer every time. Raise it (optionally with
  top-k) to sample variety; sampled turns still stream per-byte
  probabilities. Each turn's seed is derived from its turn number, so
  a sampled answer is reproducible.
- **Context meter** (under the input) — how much of the model's
  2,560-byte window the current turn is using.
- **Export chat** (header, right) — writes `talkit_chat_<stamp>.md`
  (readable) and `.json` (annotated forms, hex, per-step
  probabilities) into the Talkit folder.
- **Verify tab** — point it at a probe corpus folder (`logic_*.bin`
  with `.tags` sidecars), pick a question count, run. Reports kind
  accuracy against the 25% floor, the 4×4 confusion matrix, and
  per-family accuracy — on the active model, on your hardware. The
  classifier is the same one the training gates use.
- **Build Corpus tab** — see below.

## Building corpora with Talkit — and where the files go

The Build Corpus tab ingests dropped files (`.txt .md`, images
`.png .jpg .gif .bmp .webp .tif` or a folder of frames, sounds
`.wav`) and pasted text. Text goes through the full translator
(normalize → substitute → annotate) and the **strict** encoder — a
sentence either survives round-trip-perfect or is dropped with its
reason shown. Images and sounds become Eagle/Bat concept records in
the same byte stream. In Chat, the **→ corpus** button on any
answered turn keeps that exchange as a question-and-answer document
through the same gate.

**Where the files land:**

| action | output |
|---|---|
| Build Corpus tab → "Save corpus.bin" | `corpus.bin` **in the Talkit folder** (the exe's working directory) |
| `talkit corpus <folder>` | `corpus.bin` **inside `<folder>`**, one encoded record per usable file |
| Export chat | `talkit_chat_<stamp>.md` / `.json` in the Talkit folder |

A `corpus.bin` is concatenated ZofiaE-encoded documents, END-
delimited — training-ready input for the next model. **Never split it
on 0x00 yourself** (see the contract below); walk it with the width
rules.

## The HTTP server

`talkit serve` binds **127.0.0.1 only** — your machine's processes
can use it; the network cannot. Requests are handled sequentially
(generation already saturates the cores; the queue is the scheduler).

    GET  /health          {"ok":true,"model":"..."}
    GET  /models          {"models":[...],"active":"..."}
    POST /ask             {"question":"...",
                           "model"?: name, "temperature"?: 0.0,
                           "top_k"?: 0, "seed"?: 1, "max_new"?: 400}

`/ask` returns `answer` (rendered English), `annotated_q` /
`annotated_a` (the honest forms), `kind` (YES/NO/UNKNOWN/OPEN),
`confidence_mean` / `confidence_min`, `prompt_bytes` / `gen_bytes`,
`model`, and `drops` (sentences the translator refused, with
reasons). Naming a `model` loads and caches it on first use. One
call from anything that speaks HTTP:

```powershell
Invoke-RestMethod http://127.0.0.1:8484/ask -Method Post `
  -ContentType application/json `
  -Body '{"question":"a beetle is an insect. all insects are animals. so the beetle is an animal. if the beetle is an animal, then the horse sleeps. does the horse sleep?"}'
```

## The architecture — building a bigger one

Every ZophiaE is the same machine at different width and depth. The
invariants: **byte vocabulary 256** (no tokenizer), **context 2,560
bytes**, head_dim 64, GQA 3:1 (queries:KV), FF ratio 2.67, RoPE base
10000 with **interleaved** pairs, RMSNorm eps 1e-6 with **per-head RMS
QK-norm** before RoPE, SwiGLU, untied head. Scale is the only
variable:

| preset | d_model | layers | heads | KV | d_ff | params |
|---|---|---|---|---|---|---|
| 25m (shipped) | 384 | 16 | 6 | 2 | 1024 | 25,377,152 |
| 112m | 768 | 18 | 12 | 4 | 2048 | 113,670,144 |
| 200m | 960 | 20 | 15 | 5 | 2560 | 197,141,440 |

**The training recipe that produced the shipped numbers** (the part
that mattered more than parameters):

1. **Ration**: 10 encoded bytes per parameter **per phase**, met after
   encoding, exactly — the same architecture at half ration scored
   35.9% where v3 scores 89.1%.
2. **Phase 1 — logic school**: synthetic documents from oracle-checked
   generators across eleven logic families, **balanced to 25% each of
   YES / NO / UNKNOWN / OPEN per pattern** (so no constant answerer
   can score above chance), half single-family documents and half
   two-family composition chains. One epoch; every document seen
   once.
3. **Phase 2 — association**: 90% curated prose interleaved with
   everyday sentences, 10% **freshly generated** logic interspersed
   throughout (never replayed from phase 1 — disjointness is proven
   by hash, not hoped from seeds), single pass, with a retention
   guard watching held-out logic loss. In v3 that loss *improved*
   through 200 MB of prose.
4. **Measure with never-trained questions** balanced across families
   and kinds (the Verify tab's corpus), classified by the same rules
   the corpus gates use.

The measured lesson, stated plainly: at this size, **data ration and
corpus design were the levers; parameters were not** — scale buys
fluency on the prose side, not logic. The training side (corpus
generators, gates, trainers, exporter) lives in the simpleE project;
`tools/export_talkit_assets.py <checkpoint> <name>` writes any
checkpoint into `assets/models/<name>/` where this exe will find it.

## Wire it into your own workflow

The three pieces are **separable on purpose**. Use the translator
without the model, the codec without either, or the model behind your
own front end.

```
English  --LidiaE-->  annotated Simple English  --codec-->  concept bytes
                                                                  |
                                                                model
                                                                  v
English  <--render--  annotated Simple English  <--codec--  concept bytes
```

### Python, end to end

The Python path needs the model repo (`zofiae.py`, `simplify.py` and
`data/table/`) plus `torch`; the Rust path below needs nothing but this
exe.

```python
from simplify import Annotator
from zofiae import QA, Table, ZofiaECodec

table  = Table()                       # the dictionary
codec  = ZofiaECodec(table)            # bytes <-> annotated form
lidiae = Annotator(table, coin=True)   # English -> annotated

annotated = lidiae.annotate("All birds are animals. One bird is here.")
blob      = codec.encode(annotated)    # ends with END (0x00)
prompt    = blob[:-1] + bytes([QA])    # swap END for QA = "your turn"
# ... run the model, collect output bytes until it emits END ...
reply = codec.decode(out_bytes)
print(codec.render(reply))
```

**Just the translator** (no model, no GPU — a controlled-language
checker):

```python
from simplify import Simplifier
sim = Simplifier()
for r in sim.convert("Any English text. Multiple sentences work."):
    print(r["status"], r.get("annotated") or r.get("reason"))
```

### Rust, as a library

The crate modules are independent: `table` (dictionary), `codec`
(bytes ↔ annotated), `lidiae` (translator), `model` (inference),
`verdict` (answer-kind classification), `probe` (the four-way probe),
`serve` (the HTTP layer), `eagle`/`bat` (media → concept bytes),
`universal` (the shared math block).

```rust
let t   = table::Table::load(&assets.join("table"))?;
let lid = lidiae::Lidiae::new(&t, &assets.join("table"))?;
let m   = model::Model::load(&assets.join("models/flyweight-25m-v3/model.safetensors"))?;

let annotated = lid.annotate(&lid.substitute(&sentence))?;
let mut prompt = lid.codec.encode(&annotated)?;
prompt.pop();                       // drop END
prompt.push(codec::QA);             // "your turn"
let out = model::generate(&m, &prompt, 400);
println!("{}", lid.codec.render(&lid.codec.decode(&out)?)?);
```

For **per-token reasoning traces**, use `model::generate_traced`; for
**sampling with per-step probabilities**, `model::generate_opts`.

### The contract (what will bite you)

- **`END` (0x00) is NOT a safe delimiter.** It also appears as the
  payload byte of multi-byte codes. Splitting a corpus on 0x00 shreds
  it into convincing garbage — measured once at 244,862 fake documents.
  Walk streams with `zofiae.iter_docs(raw)` (Python) or
  `codec::iter_docs(&raw)` (Rust), which yield real document spans.
- **`QA` (0x05) marks the turn.** Encode the question, drop the trailing
  END, append QA. The model answers until it emits END.
- **Greedy by default, sampling by choice.** At `temp 0` the same input
  gives the same output, always. Sampling (GUI sliders or `/ask`
  parameters) trades that determinism for variety — seeds make it
  reproducible, but it is no longer input-determined.
- **`coin=True` vs `coin=False`.** With coins on, an unknown word is
  letter-spelled and survives. With coins off the sentence is refused.
  Corpus building uses `False` (strict); interactive use wants `True`.
- **Feature order is canonical**, not free: derivational (AGENT, ACTION,
  QUALITY, LY), then ING, then inflectional (PL, PAST, PPART, TSG, ER,
  EST), then POSS last. `archer+PL+POSS`, never the reverse.
- **Render is one-way.** bytes ↔ annotated is a bijection; annotated →
  English is display only. Never feed rendered English back in as if it
  were the annotated form.
- **Media tokens** use the `^` prefix and are shared with Eagle and Bat:
  `^eagle … ^eagle` brackets an image, `^bat … ^bat` a sound, and
  `^law.parabolic`, `^mag.q26`, `^int.7`, `^ident` are the same tokens
  in every table.

Weights ship as `model.safetensors`, fp32, flat names: `emb.weight`,
`blocks.{i}.{n1.g, n2.g, q.weight, k.weight, v.weight, o.weight, qn.g,
kn.g, w1.weight, w3.weight, w2.weight}`, `nf.g`, `head.weight`. Linear
weights are row-major `[out, in]`. The dictionary is four TSVs you can
read in any language: `lemmas.tsv`, `forms.tsv`, `aliases.tsv`,
`substitutions_approved.tsv`.

## Trust

Nothing here is trusted un-gated. Three parity gates, run any time:

    talkit parity-model     Rust logits vs PyTorch logits on fixture
                            prompts (gate: max |diff| < 1e-3; measured
                            worst 0.000030, all argmax identical)
    talkit parity-codec     encode byte-identical to Python, decode
                            round-trips, render character-identical
    talkit parity-lidiae    8,150 wild tatoeba sentences through the
                            full translator pipeline, byte-identical
                            to simplify.py including drop reasons

The parity fixtures are pinned to the default model's weights;
models added under `assets/models/` are covered by the engine gates
plus the Verify tab's behavioral numbers. Fixtures live in
`fixtures/` (dev tree), regenerated by
`tools/export_talkit_assets.py <checkpoint>`.

## Speed / footprint

~105 tokens/s CPU path (rayon matvec) for the 25M on a desktop Ryzen;
~430 MB working set. Larger models scale roughly with parameter
count. No GPU, no BLAS, no SIMD intrinsics — plain Rust.
